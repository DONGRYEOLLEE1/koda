`semverlite`가 SPEC.md를 따르도록 고쳤고, 46개 테스트 + 독립 오라클 교차검증 전부 통과했습니다.

원인별 수정 내용

semverlite/version.py
- `Version.key()`가 `str(major), str(minor), str(patch)` 를 사전순 비교하고 있어서 `"10" < "9"` → `compare("1.10.0","1.9.0") == -1` 이었습니다. 숫자(int) 비교로 바꾸고, 프리릴리스를 SemVer 규칙대로 표현하는 키로 재작성했습니다: 숫자 식별자는 `(0, int, "")`, 영숫자는 `(1, 0, str)`, 프리릴리스 없음은 `(1,)` (릴리스가 프리릴리스보다 큼). BUILD는 키에서 제외(무시)됩니다.
- 파싱 정규식이 `01.2.3`, `1.2.3-01`(숫자 식별자 선행 0), `1.2.3-a..b`, `1.2.3+b..c` 같은 빈/잘못된 식별자를 통과시켰습니다. MAJOR/MINOR/PATCH는 `0|[1-9]\d*`, PRERELEASE/BUILD는 비어 있지 않은 식별자의 점 구분 목록만 허용하고, 숫자 프리릴리스 식별자의 선행 0은 별도 검사로 거부합니다. `fullmatch` + 비문자열 인자는 `ValueError`.
- `parse`/`compare`/`sort_versions` 시그니처와 반환(입력 요소 그대로, 안정 정렬)은 그대로입니다.

semverlite/ranges.py
- `||` 미지원(`"~1.2.0 || ^1.5.0"`이 `||`를 버전으로 파싱하다 예외) → 스펙대로 comparator set 분리 후 any 매칭.
- `^`/`~` 상한이 틀렸습니다. `^`는 major 동일 여부만 봐서 `0.9.0`이 `^0.2.3`을 통과했고(0.0.x는 아예 처리 못 함), `~`는 major를 안 봐서 `2.2.5`가 `~1.2.3`을 통과했습니다. 이제 `^V`는 좌측 최상위 0이 아닌 자리를, `~V`는 MINOR를 올린 상한으로 `>=V <상한`을 씁니다.
- 프리릴리스 규칙이 전혀 없었습니다(`2.0.0-rc.1`이 `*`, `<2.0.0` 통과). 이제 프리릴리스 버전은 "같은 set 안에 동일 MAJOR.MINOR.PATCH의 프리릴리스를 가리키는 comparator가 있을 때만" 매칭합니다(`^`/`~`는 하한 V 기준).
- 빈 range/빈 set이 `ValueError` 대신 통과(`""` → `all([])` = True)하던 문제, `>= 1.2.3` 같은 공백 분리와 `1.2` 부분 버전 처리도 스펙대로 거부합니다. range 문자열은 전체를 먼저 검증하므로 일부 set이 매칭돼도 다른 set이 잘못됐으면 예외가 납니다.
- `max_satisfying`은 동일 precedence면 먼저 나온 요소를 유지하고, 입력 요소를 그대로(문자열은 문자열로) 반환하며, 잘못된 항목은 `ValueError`입니다. 다섯 공개 함수 시그니처 모두 변경 없음.

검증
- `.venv/bin/pytest -q` → 46 passed (SPEC의 유효/무효 버전 목록, precedence 체인, 정렬 안정성, caret/tilde 경계, 프리릴리스 예시 4개, `||`, 무효 range 12종, max_satisfying 포함).
- 독립 검증 스크립트(스펙 문구로 별도 구현한 오라클 + packaging 교차): 880 버전 × 26 range 매칭 일치, 전체 쌍 순서 비교 일치(packaging은 PEP 440에서 `1.0.0-2`를 post-release로 보는 등 SemVer와 상충하는 형태만 제외), 정렬/`max_satisfying` 일치, 실패 0.

판단이 필요했던 부분 두 가지: SPEC에 예시가 없는 `^0.0.0`은 `>=0.0.0 <0.0.1`로(좌측 최상위 0이 아닌 자리가 없으므로 PATCH 승급, npm 규칙과 동일) 처리했고, 잘못된 comparator가 한 set에만 있어도 range 전체를 무효로 봐서 예외를 냅니다. 변경은 커밋하지 않았습니다.
