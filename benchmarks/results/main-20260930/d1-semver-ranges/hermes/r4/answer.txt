Fixed. The whole thing works, 57 tests pass.

What was wrong
- `version.py` — `key()` compared core numbers as strings (`"10" < "9"` → the reported bug), compared prerelease by joining into one string (so `beta.2` vs `beta.11` and numeric-vs-alpha rules were wrong), and encoded "no prerelease" as an empty string, which sorted *below* any prerelease instead of above. The parse regex also allowed leading zeros (`01.2.3`) and empty prerelease/build identifiers (`1.2.3-a..b`, `1.2.3+a..b`).
- `ranges.py` — no `||` support at all, `^`/`~` used incorrect bounds (equality of MAJOR/MINOR instead of `<major+1>.0.0` / `<major>.<minor+1>.0` with the leftmost-non-zero rule), no pre-release rule, `*` ignored it too, and empty/invalid ranges weren't rejected.

What changed
- `semverlite/version.py`: strict regex (no leading zeros, non-empty idents via `_IDENTS`), numeric prerelease leading-zero check, and a totally-orderable `precedence_key()` — `(major, minor, patch, pre)` where `pre` is `(1,)` for releases and `(0, ident_keys)` for prereleases, with each identifier keyed as numeric `(0, int, "")` below alphanumeric `(1, 0, str)`. `compare` returns `-1/0/1` by comparing these keys; build is ignored. Left `key()` as a backwards-compatible alias.
- `semverlite/ranges.py`: `_parse_range` splits on `||`, validates each set/comparator (raising `ValueError` on empty sets, empty ranges, bad operators/versions), `^`/`~` compute proper upper bounds, and every non-`*` comparator carries its parsed version so a pre-release version is only allowed when some comparator in the *same* set references a prerelease of the same MAJOR.MINOR.PATCH. `max_satisfying` validates the range up front and parses every entry so an invalid version raises even if it couldn't satisfy.
- Signatures of `parse`, `compare`, `sort_versions`, `satisfies`, `max_satisfying` are unchanged.
- Added `tests/test_spec.py` covering sections 1–3 (the exact invalid list, the precedence chain, caret/tilde bounds, `||`, the pre-release rule examples, build handling, stability, and `ValueError` paths).

Verified: `.venv/bin/python -m pytest -q` → 57 passed, plus a direct script asserting the spec's literal examples. Changed files: `semverlite/version.py`, `semverlite/ranges.py`, new `tests/test_spec.py` (uncommitted).
