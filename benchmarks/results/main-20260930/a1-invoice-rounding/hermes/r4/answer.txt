Fixed. Two rule violations, both in `invoicer/money.py`:

1. Float handling (README rule 1) — `to_decimal` did `Decimal(value)`, which takes a float's binary expansion: `Decimal(2.675)` is `2.67499999999999982236431605997495353221893310546875`. It now uses the shortest `repr` for floats (`invoicer/money.py:18`), so `2.675` means exactly `2.675`. Non-float inputs are still passed straight to `Decimal`.

2. Rounding mode (README rule 2) — `quantize(CENT)` used the decimal context default `ROUND_HALF_EVEN`, so ties went to the even cent (`2.675` → `2.67`, `0.945` → `0.94`). It now passes `rounding=ROUND_HALF_UP` explicitly (`invoicer/money.py:25`).

Also wrapped `Invoice.total()` in `to_money()` (`invoicer/invoice.py:38`) — the sum of already-rounded parts is exact, so this is a no-op that keeps the two-decimal invariant explicit. Public signatures and `__all__` are unchanged (verified via `inspect.signature`).
