# TUI 가이드

`koda`(= `koda tui`)로 뜨는 Textual 화면의 구성과 표시 규칙이다. 설치와 첫 실행은 [온보딩 가이드](onboarding.md), 요약은 [기능 문서](features.ko.md#tui-와-세션) 에 있다.

> English summary: the TUI section of [features.md](features.md#tui-and-sessions) covers the same ground in short form. This page keeps the full original notes (Korean).

## 시작과 승인 모드

```bash
export DEEPSEEK_API_KEY=...       # 기본 모델의 키
koda                              # TUI 진입 (= koda tui)
koda --yolo                       # 자동 승인
```

- `--yolo` 없이 뜨면 위험 도구(쓰기·삭제·명령·MCP) 전에 승인을 묻고, `koda --yolo` 는 자동 승인한다. 재앙적 명령(`sudo`·`rm -rf /` 류)은 `--yolo` 로도 막힌다. 자세한 등급은 [온보딩 9절](onboarding.md#9-안전-모델).
- TUI 는 extra 로 설치해야 한다(`uv tool install --python 3.13 ".[tui]"`). extra 없이 설치하면 `koda` 는 설치 안내만 내고 끝나고, `koda run`·`koda chat` 은 그대로 쓸 수 있다.

## 슬래시 명령

| 명령 | 동작 |
|---|---|
| `/help` | 명령 목록 |
| `/status` | 세션·모델·컨텍스트·MCP 상태, 세션의 git 브랜치·시작 커밋 |
| `/context` | 컨텍스트 예산을 범주별(시스템 프롬프트·도구·MCP·메모리·대화 이력·턴 내부 도구 출력)로 나눠 본다 |
| `/model` | 세션 중 모델 전환. local·openai·deepseek 중 고르면 모델명·base_url·API 키를 차례로 묻는 창이 뜬다. 단축으로 `/model <모델명> [provider=…] [base_url=…] [key=…]` 도 된다. provider 가 바뀌면 그 프로필을 다시 적용한다 |
| `/mcp` | MCP 서버 상태·도구 보기와 재연결·끄기·추가·삭제 ([MCP 가이드](mcp/README.md)) |
| `/resume [id]` | 저장된 세션을 골라 열고 이어서 진행 (인자 없으면 목록에서 선택) |
| `/rename <이름>` | 세션 이름 바꾸기 (인자 없으면 현재 이름 표시) |
| `/compact` | 이력 압축 |
| `/clear` | 새 스레드 |
| `/memory` · `/remember [semantic\|episodic\|procedural] <내용>` | 영구 메모리 보기 · 넣기 (유형 생략 시 semantic) |
| `/thinking [show\|hide]` | 사고 줄 표시 전환 |
| `/theme [이름]` | 테마 전환 (인자 없으면 목록) |
| `/exit` (`/quit`) | 저장 후 종료 |

## 키

| 키 | 동작 |
|---|---|
| `Enter` | 보내기 |
| `Ctrl+J` | 줄바꿈 (터미널이 확장 키를 지원하면 `Alt+Enter`·`Shift+Enter` 도 된다) |
| `/` · `@` | 슬래시 명령 후보 · 워크스페이스 파일·폴더 후보 |
| `Ctrl+B` | 세션 패널 접기·펼치기. 패널에서 `Enter` 전환 · `n` 새 세션 · `d` 삭제 |
| `Ctrl+C` | 단계형 중단·종료 (아래) |
| `Ctrl+Q` | 바로 저장 후 종료 |

## 세션 패널

- 화면 왼쪽 세션 패널의 머리글은 현재 워크스페이스 이름(`📁 my-project`)이고, 그 아래에 세션들이 `제목 + 마지막 답변 시각` 으로 보인다. 시각은 그 세션이 마지막으로 답변을 받은 때로 고정되며 목록도 그 순서라, 세션을 오가거나 이름을 바꿔도 순서가 흔들리지 않는다.
- 행 앞 글리프는 병렬 에이전트 TUI 들의 관례를 따른다. 보고 있는 세션은 초록 `●`, 답변 중은 청록 스피너와 `답변 중`, 승인 대기는 노란 `◐`, 마지막 턴이 실패한 세션은 빨간 `✕` 와 `실패`, 나머지는 회색 `○` 다. 두 번째 줄에는 그 세션이 작업한 git 브랜치와 마지막 답변 시각이 함께 보인다.
- 목록에서 Enter 로 전환하고, `n` 새 세션, `d` 삭제(확인 모달, 보고 있는 세션과 답변 중인 세션은 불가), `Ctrl+B` 로 접고 펼친다. 터미널이 100열보다 좁으면 접힌 채 시작한다.

## 병렬 세션

- 세션은 서로 독립적으로 돈다. 한 세션이 답변하는 동안 패널로 다른 세션을 열어 바로 질의할 수 있고, 배경 세션의 답변은 자기 대화 영역에 계속 쌓이다가 끝나면 알림이 뜬다.
- 답변 중인 세션에서는 그 턴이 끝날 때까지 입력창이 잠기므로, 전환은 패널(`Ctrl+B` → ↑↓ → Enter)로 한다.
- 배경 세션이 위험 도구 승인을 요청하면 화면을 가로채지 않고 패널에 `승인 대기` 로 표시했다가 그 세션을 열 때 묻는다.

## 세션 기록과 제목

- 세션에는 작업한 git 브랜치와 시작 시점의 커밋이 함께 기록된다(`/status` 로 확인). 세션 파일은 `<workspace>/.koda/sessions/<id>.json` 이다.
- 세션 제목은 첫 실질 턴이 끝난 뒤 질의와 답변을 보고 LLM 이 10~15자로 짓는다. 인사말처럼 내용이 빈약하면 다음 실질 턴에서 한 번 더 시도하고(세션당 최대 2회), 그때까지는 첫 질의 앞부분이 임시로 보인다.
- 문맥 압축이 일어나면 압축 요약이 제목을 함께 갱신하며, `/rename <이름>` 으로 직접 바꾼 제목은 자동 갱신이 덮지 않는다.

## 상태줄과 컨텍스트 게이지

- 입력창 위 상태줄은 `모델 · 승인 모드(yolo·manual) · ⎇ 브랜치 · mcp N · 컨텍스트 게이지` 다.
- 게이지는 **프롬프트에 실제로 실리는 전부**(시스템 프롬프트·메모리·스킬·도구 스키마·대화 히스토리·그 턴의 도구 출력)를 `CONTEXT_BUDGET_TOKENS`(기본 122k)와 견준다. 첫 턴 전에는 고정 몫을 정적으로 추정해 보이고, 턴이 돌면 실제 관측 토큰 중 최대값을 쓴다. 절반을 넘으면 노랑, 80% 를 넘으면 빨강이다.
- MCP 도구를 많이 붙이면 스키마만으로 게이지가 크게 오르므로(도구 74개면 약 61k 토큰) 안 쓰는 서버는 `koda mcp disable` 로 꺼 두는 편이 좋다. 내역은 `/context` 에서 범주별(시스템 프롬프트·도구·MCP·메모리·대화 이력·턴 내부 도구 출력)로 나눠 볼 수 있다.
- 진행 상태는 바로 위 활동바(스피너·단계·경과)가 말하므로 상태줄에 문구로 겹쳐 쓰지 않는다.

## 입력창 자동완성

- 입력창에서 `/` 를 치면 슬래시 명령 후보가 설명과 함께 뜨고 이어서 치는 글자에 맞춰 좁혀진다. ↑↓ 로 고르고 Tab/Enter 로 채우며, 명령을 다 치면 후보가 사라져 Enter 가 그대로 실행한다.
- 입력창에서 `@` 를 치면 워크스페이스의 파일·폴더 후보가 최대 5건 뜨고, 이어서 치는 글자에 맞춰 바로 갱신된다(경로 접두 → 파일명 접두 → 부분 일치 → 순서 부분열 순). ↑↓ 로 고르고 Tab/Enter 로 채우며, 폴더를 고르면 `폴더/` 까지 채워지고 하위 후보가 이어진다. Esc 로 닫는다.

## 중단·종료·복사

- `Ctrl+C` 는 단계형이다. 답변 중에 한 번 누르면 그 턴을 중단하고(부분 답변은 히스토리에 남기지 않음), 2초 안에 한 번 더 누르면 세션을 저장하고 종료한다. 대기 중에는 첫 번째가 종료 예고, 두 번째가 종료다. `Ctrl+Q` 는 바로 저장 후 종료.
- 마우스로 드래그해 놓으면 그 텍스트가 클립보드로 복사된다(OSC 52, tmux 는 `set-clipboard on` 필요). 선택이 남아 있으면 `Ctrl+C` 는 중단·종료가 아니라 복사다.

## 턴 표시

- 턴이 끝나면 답변 아래에 `✓ 완료 · N초`(편집 경로면 검증 결과까지)만 남는다. 경로(route)와 langfuse trace 주소는 진단용이라 표시하지 않으며 `/status` 와 langfuse 에서 본다.
- 편집 도구(`edit_file`·`multi_edit`·`patch_file`)가 만든 diff 는 과정 그룹 밖 대화에 색상 그대로 붙는다. 결과이므로 턴이 끝나 과정이 접혀도 남고, 펼치는 클릭 없이 바로 보인다.
- 답변 전 과정(사고·툴 호출)은 흐린 한 줄 스텝으로 `과정` 그룹 안에 쌓인다. 연속된 읽기·검색·조사는 `⏺ 탐색 · a.py, b.py 읽음 · "add" 검색` 한 줄로 합쳐지고, 모델이 사고 내용(`reasoning_content`)을 따로 주면(vLLM·DeepSeek) `∙ 첫 문장` 으로 보인다.
- 턴이 끝나면 그룹이 `▸ 과정 · 사고 N · 탐색 N · 편집 N · Ns` 로 접히며, 클릭하면 다시 펼쳐 각 스텝의 출력 전체를 볼 수 있다(접힌 상태에서는 드래그 선택이 되지 않는다).
